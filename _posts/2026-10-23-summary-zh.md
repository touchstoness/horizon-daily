<a id="item-ai-platform-1"></a>
### [Databricks 谈 AI 成本治理](https://www.databricks.com/blog/ai-bill-coming) ⭐️ 8.0/10

Databricks 联合创始人 Patrick Wendell 在访谈中介绍，公司大规模采用 AI 编程智能体后，按用量计费的模型调用曾使成本快速攀升，进而构建了开发者与模型之间的内部控制层，并以此启发 Unity Gateway。按他的描述，Unity Gateway 承担逐级成本管控：先警告、再要求审批、随后切换至更便宜的模型，把彻底停止调用作为最后手段，以减少研发人员在任务中途被打断的情况。他表示，Databricks 目前人均 token 支出已大致持平，同时总使用量和价值仍在增长；定期向员工发送个人支出明细与节省建议这一措施，据其称可带来约 10% 的节省。文章导语还称单位成本最高降低了 90%，但所提供正文不完整，未披露这一数字的具体措施、统计口径，也未说明 Unity Gateway 的对外可用范围或价格。

rss · Databricks Blog · 10月22日 18:12

**「背景」** Databricks 将 AI 编程工具的成本问题归因于消费计费模式：模型调用按用量计费，单个用户的支出理论上没有固定上限。该公司先在内部为自身的 AI 支出构建控制层，随后将这一做法发展为 Unity Gateway。

**「平台启示」** 这项实践为企业智能体平台提供了一个具体设计参考：在开发工具与模型之间集中执行成本策略，并将警告、审批和模型降级串成逐级管控流程。Wendell 提到，硬性额度限制可能促使员工转用个人账号、使企业失去调用可见性，因此成本治理需要同时考虑预算约束、任务连续性和统一入口的使用意愿。

### [Claude 新增云端托管选项](https://cloud.google.com/blog/products/ai-machine-learning/expanding-claude-availability-on-google-cloud/) ⭐️ 8.0/10

Google Cloud 宣布，Claude 的 Anthropic 托管部署选项正式可用，与现有 Google 托管选项并行，供企业按数据处理责任、治理需求和平台功能获取方式选择。公告称，两种模式均在模型发布首日提供相同模型、采用相同价格并通过 Google Cloud 计费，所列模型包括 Claude Fable 5.1、Sonnet 5.5、Haiku 5.5 和 Opus 5.5。新模式由 Anthropic 在 Google Cloud 基础设施上作为数据处理方运营，适用 Anthropic 服务条款，可即时获取新发布的 Claude 平台功能，包括仍处于测试阶段的 Claude Managed Agents，以及 skills 和代码执行；企业仍可使用 Google Cloud IAM、Cloud Audit Logging，并将支出纳入现有 Google Cloud 账单及符合条件的承诺消费。

rss · Google Cloud AI Blog · 10月22日 21:00

**「背景」** 现有 Google 托管模式由 Google Cloud 在既有客户协议下担任数据处理方，提供 VPC Service Controls、客户管理的加密密钥（CMEK），以及美国、欧盟和亚太地区的数据驻留选项，并原生集成 BigQuery 和 Model Armor。该模式同样支持最新 Claude 模型首日可用，但新的 Claude 平台功能需要完成与 Google 托管基础设施的集成后再陆续推出。

**「平台启示」** 这项部署设计将“模型可用性与价格”同“数据处理责任与平台功能上线节奏”分开：企业即使保留统一身份认证和计费入口，仍需单独评估运行栈的责任边界。对 CRM+AI 平台而言，部署模式应成为治理配置的一部分，不能仅凭模型名称相同，就认定其合同条件、治理能力和 Agent 功能可用性一致。

### [Neo4j 演示 KYC 文档受益人追查](https://neo4j.com/blog/graph-database/finding-the-ultimate-beneficial-owner-in-a-pile-of-kyc-documents-with-document-intelligence/) ⭐️ 7.0/10

Neo4j 发布技术教程，介绍使用 Document Intelligence 将 KYC 文档转为知识图谱，再结合 Cypher 与 Louvain 社区发现算法追查贷款申请企业背后的最终受益所有人（UBO）。示例围绕 Anchor Point Partners 的 20 份文档展开，调查线索是一名未列入直接股东名单、且与申请企业关系未明确说明的个人担保人。文中称，Document Intelligence 可在 Aura Console 中接收纯文本、PDF 和 Word 文件，通过自然语言指导实体与关系抽取、调整模型，并将图谱导入空的 AuraDB 实例；其“无代码”描述针对构图环节，后续分析所列环境还包括 Python、Jupyter 与 Aura Graph Analytics API 凭据。所给正文在分析步骤前截断，未展示最终识别结论、效果验证或真实客户落地数据。

rss · Neo4j Blog · 10月22日 12:48

**「背景」** 该示例的 KYC 材料包括注册文件、所有权披露、董事会纪要、贷款申请、制裁筛查记录和新闻剪报，需要跨文档拼接人物与企业之间的联系。最终受益所有人调查关注企业背后的最终受益或控制关系，因此，个人未出现在直接股东名单中，并不能单独回答其与申请企业的实际关系。

**「建模启示」** 这套流程将文档抽取、关系模型审阅与后续图分析分开，并允许用户用自然语言补充人物与企业之间的 OWNS 关系，可为 CRM 客户关系分析和 KYC 文档建模提供具体参考。Neo4j 明确说明 LLM 抽取结果不具确定性，并提供数据库备份供教程复现；企业设计类似流程时，应保留模型与抽取结果的审阅环节，并明确分析所用的数据版本。
