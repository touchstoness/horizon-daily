### [AWS 与 Okta 治理智能体访问](https://aws.amazon.com/blogs/machine-learning/govern-ai-agent-access-with-okta-cross-app-access-and-amazon-bedrock-agentcore-part-1/) ⭐️ 8.0/10

AWS 在《Part 1》博客中介绍了 Okta Cross App Access（XAA）与 Amazon Bedrock AgentCore 的集成：Okta 负责注册智能体、审批其可访问的应用，并在每次代理用户请求时评估策略；AgentCore Runtime 验证授权，AgentCore Identity 在智能体代码不可见凭据的情况下兑换并保管短期访问令牌。文中给出的测试称，移除用户对智能体的分配后，Okta 约 1 秒内拒绝该用户的新请求，已签发令牌在 5 分钟内过期；AgentCore Identity 为一次约 30 秒的端到端请求增加约 0.6 秒。该方案面向智能体代表用户读取客户记录、更新工单等跨应用操作，但材料未说明完整集成的可用范围或生产环境验证情况。

rss · AWS Machine Learning Blog · 11月6日 17:09

**「背景」** 传统的按应用 OAuth 同意和共享服务账号，难以集中回答某个智能体能否代表特定用户访问特定应用，以及如何及时停止访问。本文将 Okta Cross App Access 作为治理平面，由其评估智能体、用户与目标资源之间的授权关系；Amazon Bedrock AgentCore Runtime 和 AgentCore Identity 则负责验证授权、保管凭据并换取短期访问令牌。

**「平台启示」** 材料将架构明确分为治理平面与执行平面：Okta 决定“哪个智能体可代表哪个用户访问哪个资源”，AgentCore 负责执行该决定并管理凭据。每次请求使用用户 ID 令牌、Okta 的单次使用 ID-JAG 和资源接受的访问令牌分别承载身份、授权决策与资源访问，企业平台可据此将授权评估、令牌兑换、凭据隔离和工具层权限校验拆分治理。

**标签**: `#Amazon Bedrock AgentCore`, `#Okta Cross App Access`, `#智能体身份与权限`, `#跨应用访问治理`, `#令牌撤销与过期`

### [Greenlight 在 AgentCore 上构建 Luna](https://aws.amazon.com/blogs/machine-learning/how-greenlight-financial-built-an-autonomous-soc-solution-on-amazon-bedrock-agentcore/) ⭐️ 8.0/10

AWS 博客介绍，Greenlight Financial 使用 Amazon Bedrock AgentCore 的 Runtime 托管 Luna 智能体代码，并使用 Memory 支持分层多智能体系统，处理暗网泄露卡、身份异常、基础设施告警和金融风险事件。Luna 采用分层监督架构，包含 30 多个专用 Agent；AWS 称其每月处理最多 4,000 起安全与风险事件，其中超过 90%无需人工介入，并可在数秒内完成部分分诊。该方案面向受金融监管约束的企业安全运营和金融风险分诊场景，但上述生产指标来自厂商介绍，材料未提供独立验证方法、成本、权限控制或可观测性细节。

rss · AWS Machine Learning Blog · 11月6日 16:55

**「背景」** 安全运营中心（SOC）的告警研判往往需要跨系统核查证据；据 AWS 博客介绍，Greenlight 分析师处理一条暗网银行卡泄露通知时，需要检查卡片状态、历史通知、客户会话及客服工单，单案耗时约 15–30 分钟。Luna 采用的分层监督架构对应其安全团队的工作分工：第一层处理大量初步研判，第二层处理复杂情况，复杂案件仍需携带完整上下文升级给人工分析师。

**「平台启示」** 该案例将企业 Agent 平台拆分为运行时托管、记忆能力、分层监督编排和领域专用 Agent：高频简单事件由 L1 处理，复杂事件升级至 L2 并携带上下文交给人工。对 CRM+AI 产品而言，这种分层架构可作为将统一运行时与领域工具、长期或情景记忆及人工升级机制组合起来的参考。
