### [Foundry 托管 Agent 私网排障](https://devblogs.microsoft.com/foundry/hosted-agents-private-network-setup/) ⭐️ 8.0/10

微软发布 Microsoft Foundry 托管 Agent 的私网部署排障指南，面向关闭公网访问、将 Agent 注入自有 VNet，并通过私有端点连接 Azure Cosmos DB、Storage、Azure AI Search 和 Key Vault 的企业场景。文章披露，委托的 Agent 子网承载会话 micro VM 和每项目一个的单租户数据代理；工具调用由该代理转发，平台还需从该子网使用托管身份登录 Microsoft Entra ID。针对 Agents 页面超时，指南给出五项网络检查，并明确常见的“Listing agents timed out”通常表示数据代理无法及时访问自带的 Cosmos DB，重点应核查子网配置、私有端点、DNS、Entra 登录路径及防火墙 TLS 检查。该内容是运维排障指南而非新功能发布；微软还提示，托管 Agent 的网络注入必须在首次创建 Foundry 账户时配置，不能事后添加。

rss · Microsoft Foundry Blog · 11月21日 18:12

**「背景」** 10 月 29 日的 Horizon 日报曾报道，Microsoft Copilot harness 已在 Foundry Agent Service 中进入公测，托管运行时负责 Agent Loop、沙箱、工作上下文及模型与工具调用编排。此次文章并非新的产品发布，而是进一步说明托管 Agent 接入自有 VNet 后的运行时网络依赖与排障方法，包括会话 micro VM、项目级单租户数据代理、私有端点和托管身份访问链路。

**「平台启示」** 该架构将会话计算、项目级数据访问代理和企业数据资源分层：Agent 不直接访问后端资源，而由单租户数据代理经私有端点转发。对 CRM+AI 私网方案而言，运行时连通性检查不应只覆盖业务数据库，还应同时验证私有 DNS、身份认证出口、跨 VNet 路由和 TLS 检查策略。

机器之心介绍了西北工业大学提出的多模态终身知识编辑方法 ROSE，文章标题将其标注为 NeurIPS 2026 Spotlight。该研究面向多模态大模型持续吸收 CEO 更替、产品迭代和赛事结果等新事实时的新旧知识冲突，并关注预训练通用能力的保留。现有材料未披露 ROSE 的具体架构、编辑机制、实验数据及适用边界，因此目前只能确认其研究目标，尚不足以判断其在企业知识更新和模型维护场景中的实际效果。

**「背景」** 终身知识编辑关注模型在多轮、持续的事实更新中吸收新知识，而不只是完成一次性修改。其核心难点包括减少新旧知识冲突，并尽量保留模型预训练阶段形成的通用能力；这与企业中的人员、产品和业务事实持续变化直接相关。
