### [AgentCore Evaluations 接入决策模型](https://aws.amazon.com/blogs/machine-learning/use-decision-models-with-amazon-bedrock-agentcore-evaluations/) ⭐️ 8.0/10

AWS 介绍了在 Amazon Bedrock AgentCore Evaluations 中通过代码评估器接入决策模型，用于将智能体状态映射为固定标签及其概率分布，便于设定阈值并以程序处理。AgentCore Evaluations 支持开发阶段按需评估、对存储会话进行批量评估，以及针对生产流量在线评估；还提供 15 个内置评估器和自定义评估器。博客展示了 TypeSafe 托管的 Jev 和开源的 Strands Decider 2B 两种后端，并将决策模型定位为筛选层，可挑出需要内置评估器进一步分析的会话；文中未提供实测数据或客户落地证据。

rss · AWS Machine Learning Blog · 11月4日 18:46

**「背景」** AgentCore Evaluations 的自定义评估器可采用基于 Amazon Bedrock 模型的 LLM-as-a-judge，也可运行在 AWS Lambda 中的代码逻辑，后者能够调用外部系统、模型或 API。决策模型针对预先定义的选项输出概率分布；与生成自由文本解释的 LLM 评估器相比，它更适合答案集合固定、需要可编程评分的问题。

**「平台启示」** 材料展示了一种分层评估设计：先用决策模型对策略合规、工具调用安全或检索内容一致性等固定问题作概率评分，再将需要调查的轮次交给能提供解释的内置评估器。对企业智能体平台而言，这种组合可把快速筛查与深入诊断放在同一评估流程中；博客没有给出其成本或效果数据。

### [Amazon Quick 上线智能审批](https://aws.amazon.com/blogs/machine-learning/smart-approvals-in-amazon-quick-human-oversight-where-it-matters/) ⭐️ 8.0/10

AWS 宣布在 Amazon Quick 中提供 Smart Approvals：它在既有权限与审批控制内，将符合条件的智能体操作与用户请求进行比对，自动批准常规操作，并把未获批准、超时或审查失败的操作交还用户确认。该能力默认开启，但仅适用于用户设置为“每次询问”且没有其他控制要求人工审批的操作；管理员可通过 Custom Permissions 限制使用，用户也可自行关闭。自动批准为一次性授权，只覆盖已审查的具体操作及参数，不会扩大持续权限；AWS 未提供定价、落地规模或性能数据。该能力适用于企业智能体执行消息发送、记录变更和跨系统操作等多步骤任务时，在减少重复确认的同时保留高风险操作的人审环节。

rss · AWS Machine Learning Blog · 11月4日 16:33

**「背景」** Amazon Quick 将权限控制与人工审批分开处理：现有权限和策略决定智能体能否执行操作，Smart Approvals 则评估获准操作是否仍需人工判断。AWS 此前介绍过将执行前授权、人工观察或接管及审计纳入 Agent 平台的做法；2026 年 10 月 30 日日报报道的 Epsilon UI 测试方案将这些控制用于浏览器智能体，而此次 Amazon Quick 进一步介绍了按用户请求评估操作、减少常规审批提示的机制。

**「平台启示」** Smart Approvals 将“模型判断”与“权限执行”分层：独立分类器结合有限会话上下文和账户内知识图谱判断操作是否需要人审，权限服务则继续执行 Custom Permissions、Guardrails 及连接器权限。对 CRM+AI 平台而言，可参考这种单次、参数级授权机制，并将外发数据、访问变更、删除记录和支付等操作固定在不可被模型绕过的强制审批策略中。
