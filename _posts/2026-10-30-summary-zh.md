### [Salesforce 拟收购 Rune](https://www.salesforce.com/news/stories/salesforce-signs-definitive-agreement-to-acquire-rune-technologies/) ⭐️ 7.0/10

Salesforce 已签署收购边缘原生技术商 Rune Technologies 的最终协议，但交易尚未完成，官方未披露金额。交易完成后，Rune 面向低连接或无连接的 DDIL 环境所提供的供应需求预测、资源优化和前线决策能力，将被用于扩展 Missionforce，使军事物流数据与企业侧人员、设备、资产及维护流程衔接。Salesforce 宣称，其国防业务同比增长 80%，客户覆盖美国六大军种，并已获得一份合同上限为 56 亿美元的美国陆军十年期合同；相关能力适用于军队、盟国国防部门及防务机构的战术边缘物流和持续保障场景。

rss · Salesforce News · 10月29日 20:00

**「背景」** Missionforce 是 Salesforce 一年前推出的政府智能体平台，旨在将 AI、数据、应用与云技术用于政府关键任务。此次所涉 DDIL 指网络被拒止、受损、间歇或受限的环境，军事前线团队在这类场景中可能仅有少量连接或完全离线。

**「竞争启示」** 这项并购体现了“边缘决策层＋企业记录与流程层”的分层思路：前线在断网或弱网条件下继续处理物流与保障任务，恢复连接后再与企业系统同步。对 CRM+AI 平台而言，面向受限网络行业的 Agent 设计不仅需要模型和工作流能力，还需考虑离线运行、统一记录及连接恢复后的数据协调机制。

### [Epsilon 用 Nova Act 扩展 UI 测试](https://aws.amazon.com/blogs/machine-learning/building-intent-driven-ui-testing-with-amazon-nova-act/) ⭐️ 8.0/10

AWS 披露，Epsilon 已将 Amazon Nova Act 与 Amazon Bedrock AgentCore Browser 集成到内部共享 Agentic Platform，为产品团队提供多租户、意图驱动的 UI 测试服务，同时继续以 Playwright 作为确定性回归测试主干。该平台由 50 名工程师组成的团队建设，统一提供技能式 Agent Builder、联邦身份、执行前授权、MCP 集成及跨账户配置；浏览器侧采用隔离的临时会话，并支持人工观察或接管、将会话录像保存至 Amazon S3 以及通过 AWS CloudTrail 审计。该方案适合需要跨产品团队复用浏览器基础设施和权限治理、又希望用自然语言测试补充选择器脚本的企业；AWS 称自然语言步骤更能适应外观变化，但现有材料未提供完整的实测结果、价格或可用范围。

rss · AWS Machine Learning Blog · 10月29日 18:20

**「背景」** Epsilon 原有的 Playwright 回归测试仍是其确定性功能检查的主干，但这类脚本依赖选择器和页面结构，可能因外观调整而需要维护。此次方案并非替代 Playwright，而是在其上增加以自然语言描述步骤的意图驱动测试，并由共享平台统一提供浏览器基础设施、身份与权限能力。

**「平台启示」** Epsilon 将 UI 测试封装为共享智能体平台上的托管能力，而不是让各团队分别配置浏览器、身份和模型集成，体现了“统一治理与运行时底座、按技能交付能力”的平台分层方式。其保留 Playwright 处理确定性回归、以 Nova Act 补充意图测试的组合，也说明智能体测试可先作为现有自动化体系的增量层，而非直接替代。

### [AgentCore 接入 400 个私有 API](https://aws.amazon.com/blogs/machine-learning/how-moengage-turned-over-400-apis-into-agent-tools-with-agentcore-gateway/) ⭐️ 8.0/10

MoEngage 采用 Amazon Bedrock AgentCore 的 AgentCore Gateway，将约 400 个内部 REST API 转换为按权限限定的智能体工具；这些 API 由 25 个工程团队维护，分布在七个 AWS 区域的私有 VPC 中，无须开放公网端点。其做法是由产品团队继续提供 REST API 和 OpenAPI 规范，由 AI 平台团队统一负责 MCP 层，而非让各团队分别建设和维护 20 多个 MCP 服务器。AWS 与 MoEngage 称，该方案节省了约六个月的平台工程工作量，并将新 API 的接入时间从数天缩短至数小时；这类架构适用于需要让营销、客户互动等智能体安全调用既有企业能力的场景，但相关成效数据来自厂商与客户自述。

rss · AWS Machine Learning Blog · 10月29日 16:54

**「背景」** MCP 为智能体发现和调用工具提供标准接口，但若由各工程团队分别部署 MCP Server，会增加协议适配、运维和跨服务调用的复杂度。MoEngage 因此保留各团队以 REST API 和 OpenAPI 规范交付能力的方式，由 AI 平台团队通过 Amazon Bedrock AgentCore Gateway 统一管理 MCP 接入层。

**「平台启示」** 该案例体现了一种职责分层：业务团队以 OpenAPI 规范声明可用操作，中央 AI 平台统一完成工具生成、私网连接和服务端授权，从而避免把 MCP 实现与运维责任分散到各业务团队。对 CRM+AI 平台而言，这种集中工具入口也有助于跨营销活动、客群查询和投递统计等领域组合调用，同时不让模型直接控制身份权限。

**标签**: `#AgentCore Gateway`, `#智能体工具调用`, `#API 网关`, `#私有 VPC`, `#身份与权限`
