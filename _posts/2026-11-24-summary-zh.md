### [AlloyDB Omni 接入本地模型](https://cloud.google.com/blog/products/databases/alloydb-omni-integration-with-local-models/) ⭐️ 7.0/10

Google Cloud 宣布，支持任意位置运行且兼容 PostgreSQL 的 AlloyDB Omni 现可连接 Gemma 4、Qwen3.8 等本地托管大模型，并由数据库通过 SQL 直接调用本地模型服务器。该集成已经可以在自有机器上测试；官方示例使用 GKE、AlloyDB Omni Kubernetes Operator、googleMLExtension 和 Ollama 完成部署及模型注册。AlloyDB Omni 还提供向量嵌入存储、语义搜索和 ScaNN 索引，适用于隔离网络、数据驻留要求下的日志分析、内部文档摘要和本地聊天机器人；Google 称本地部署可使提示词、数据和响应留在企业环境内。

rss · Google Cloud AI Blog · 11月23日 17:00

**「背景」** AlloyDB Omni 是 AlloyDB 的可下载、跨环境运行版本，可部署在企业自有基础设施及本地环境；其内置 AI 能力包括 ScaNN 向量索引技术。此次本地模型集成建立在这一数据库侧向量存储与检索能力之上。

**「平台启示」** 这一方案将数据库、向量检索与模型推理解耦：模型以独立本地服务部署，再通过注册机制供 SQL 调用，有利于企业在保留既有数据层的同时替换模型。当前材料未披露接口权限、调用审计、故障处理、性能或生产客户数据，这些仍是评估私有化 AI 运行时可用性的关键项。

OpenAI 发布 GitHub-only 预览版 Agents SDK v1.0.0-alpha.2，新增基于 Responses 或 Codex 的跨 worker 会话与待审批恢复，并支持恢复部分 Codex 原生命令及文件编辑审批。该版本还加入工具执行钩子、函数工具过滤、可选的 Runner 文本脱敏和细粒度操作追踪，可用于需要人工审批、故障接续、工具权限治理及审计的企业 Agent 场景。预览版支持 CPython 3.10–3.14，并提供 Linux x86-64/ARM64、Apple Silicon macOS 11+ 和 Windows x64 安装包；目前并非稳定版本，也未披露价格或规模化应用数据。Alpha.2 会读取 Alpha.1 的 RunState schema 1.22、写入 schema 1.24，而 Alpha.1 无法读取新快照，因此 OpenAI 明确要求先升级检查点读取端，再升级写入端。

github · markstuart-oai · 11月23日 20:11

**「背景」** 11 月 21 日的 Horizon 日报曾报道，Agents SDK v1.0.0-alpha.1 首次加入可按运行选择的 CodexProvider，并支持工具调用前审批；本次 alpha.2 在此基础上增加了跨 worker 恢复会话、待审批状态及部分 Codex 原生审批的能力。alpha.2 会读取 alpha.1 的 RunState schema 1.22，但写入新的 schema 1.24，旧版无法读取新快照，因此共享检查点的部署需先升级读取端。

**「集成启示」** 该版本将会话历史与待审批状态共同纳入 ResumableSession 检查点，并要求存储支持原子条件写入及单会话单写入者，为多 worker Agent 的状态一致性提供了具体实现方式。企业升级持久化格式时可参考其“先读后写”顺序，同时在恢复执行前核对工作区、权限、工具声明、授权策略和外部副作用，避免把状态恢复误当作业务操作已安全回滚。
