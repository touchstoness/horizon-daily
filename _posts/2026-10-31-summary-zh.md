### [Agent Compute Engine 亮相](https://cloud.google.com/blog/topics/ai-infrastructure/whats-new-in-ai-infrastructure-this-month/) ⭐️ 8.0/10

Google Cloud 在 10 月 AI 基础设施更新中发布面向自主智能体的 Agent Compute Engine，采用硬件隔离的 microVM 沙箱，并配套 Agent Gateway 和 Agent Registry，以支持运行隔离、身份管理与治理。Google Cloud 宣称该服务可实现亚秒级启动，并通过写时复制内存共享提高工作负载密度，同时提供跨云可观测性；原文未披露定价、客户案例及具体可用区域。该服务适用于企业部署需要快速弹性扩缩、安全隔离和统一治理的多智能体工作负载。

rss · Google Cloud AI Blog · 10月30日 16:00

**「背景」** Agent Compute Engine 面向自主智能体的运行时需求，将硬件隔离的 microVM 沙箱与 Agent Gateway、Agent Registry 等治理组件组合在同一服务中。此次月度更新还同时覆盖 GKE、Cloud Run 和开源推理栈 llm-d，显示 Google Cloud 正从底层算力、容器与工作流到智能体运行和治理分层提供基础设施能力。

**「平台启示」** Agent Compute Engine 将 microVM 执行沙箱与网关、注册中心分层组合，表明企业智能体平台可把运行时隔离、流量入口和资产治理作为独立但协同的基础能力。写时复制内存与快速启动则针对智能体任务短时、突发和高并发的运行特征，但其密度与性能收益目前仅有厂商表述。

### [Neo4j 图支撑 Fabric 反欺诈](https://neo4j.com/blog/graph-database/unmasking-fraud-neo4j-in-microsoft-fabric/) ⭐️ 6.0/10

Neo4j 官方博客介绍了一种面向 P2P 支付欺诈调查的方案：Microsoft Fabric 将交易日志与客户数据汇集到 OneLake 的开放 Delta 表，Neo4j Graph Intelligence 再将账户、银行卡、电话号码、设备、IP 地址和交易之间的关系建模为属性图，为 Copilot 和 AI 智能体提供关系上下文。该方案可按连接强度和网络结构识别协同欺诈，并过滤公共 Wi-Fi、机场网络或运营商网关等高流量节点造成的误报；Neo4j 宣称其可在毫秒级发现隐藏欺诈团伙。文章属于方案介绍，未披露明确的新产品版本、价格、可用范围、客户案例或效果数据。

rss · Neo4j Blog · 10月30日 15:43

**「背景」** Microsoft Fabric 通过 OneLake 将交易日志和客户数据汇集为开放的 Delta 表；Neo4j Graph Intelligence 则可在这些表之上构建属性图，把账户、银行卡、电话号码、IP 地址和交易表示为实体及其关系。相较依赖多表连接的 SQL 查询，图模型更适合分析多跳关联，并可按连接类型与网络结构区分私人凭证共用等高价值信号和公共 Wi-Fi 等高频噪声。

**「建模启示」** 企业可将交易与客户主数据保留在湖仓层，再增加图关系层供 Copilot 查询；在反欺诈模型中，不应把所有共享属性视为等价连接，而应结合标识符稀缺度、节点流行度和多跳网络结构区分公共基础设施与高风险关联。
