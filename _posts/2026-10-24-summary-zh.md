### [SageMaker AI 多轮强化学习指南](https://aws.amazon.com/blogs/machine-learning/multi-turn-reinforcement-learning-on-amazon-sagemaker-ai-a-hands-on-guide/) ⭐️ 8.0/10

AWS 发布实操指南，介绍如何使用 Amazon SageMaker AI 开展多轮强化学习：训练服务通过 AWS Lambda 转发器调用部署在 Bedrock AgentCore、EKS、EC2 或 Fargate 上的智能体，并根据完整任务结束时的奖励信号训练策略模型。示例中，智能体执行多轮 Wordle 任务，GRPO 根据同一题目的多次 rollout 奖励差异更新 LoRA 适配器；AWS 报告称，gpt-oss-20b 在保留词集上的解题率由默认推理强度下的 61% 提升至 84%，在训练所用的低推理强度下由 15% 提升至 69%，训练 token 成本约为 339 美元。该指南已提供配套 aws-samples 代码，适用于费用报销、工单分流等以流程最终成败为反馈的企业多步骤任务，但正文未提供生产客户案例。

rss · AWS Machine Learning Blog · 10月23日 17:48

**「背景」** 单轮监督微调通常需要目标答案或轨迹标签，而多步骤智能体可能存在多条有效执行路径，早期动作也要到流程结束后才能判断效果。该方案因此不要求数据集给出正确轨迹，而是让智能体与环境多轮交互，并以最终结果奖励分配训练信号。

**「平台启示」** 该方案将训练任务和策略模型置于 SageMaker AI，将智能体、业务环境与奖励函数放在 AgentCore 等运行时，再通过 Lambda 转发器和兼容 OpenAI 的训练端点连接两层。这种分层使企业可以保留既有智能体部署位置，并把任务数据简化为环境初始条件，但仍需围绕最终业务结果设计可客观计算的奖励。

### [Spark 声明式管道 Agent 测试](https://www.databricks.com/blog/built-agents-case-spark-declarative-pipelines) ⭐️ 7.0/10

Databricks 使用同一款 Opus 4.8 Agent，对 22 项数据工程任务和每项 12 组输入数据分别生成过程式 PySpark 与 Spark Declarative Pipelines，共测试 528 条管道；盲测式自动评分显示，两种方式分别完成 255/264 和 258/264 次构建。Databricks 据此主张，声明式管道可在执行前通过 Spark dry run 检查部分结构性错误，并由 Spark 负责执行顺序和结果保存，从而减少 Agent 编写及人工审查的样板代码；但原文所称“更安全、更便宜、更精简”缺少完整量化结果。厂商还称，其平台上超过 70% 的 Spark Declarative Pipelines 已由 Agent 创建，这套模式适用于企业以 Agent 生成、验证和迭代生产数据管道的场景。

rss · Databricks Blog · 10月23日 19:00

**「背景」** 在过程式 PySpark 管道中，开发者或 Agent 不仅要编写数据转换逻辑，还要负责步骤排序和结果落表；Spark Declarative Pipelines 则由作者描述目标数据集及其查询，让 Spark 处理执行顺序和结果保存。后者还能在实际运行前通过 dry run 检查部分结构性问题，但无法据此发现所有只会反映在输出结果中的静默错误。

**「平台启示」** 企业 Agent 工具链可将“声明式数据定义、运行前结构检查、运行时编排”拆成不同层，让 Agent 聚焦数据集及查询逻辑，并把依赖排序和持久化交给平台。该测试也表明，评估 Agent 数据工程能力时应同时记录任务完成率、失败后的重试次数和运行成本，而不能只比较最终输出是否正确。

**标签**: `#Databricks`, `#Spark声明式管道`, `#Agent代码生成`, `#数据工程`, `#企业AI运行时`
