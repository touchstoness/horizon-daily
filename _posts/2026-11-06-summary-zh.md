### [OpenSharing 扩展共享边界](https://www.databricks.com/blog/delta-sharing-opensharing-what-changed-whats-next) ⭐️ 8.0/10

Databricks 称，Delta Sharing 已演进为 Linux Foundation 旗下的厂商中立开放协议 OpenSharing，并于 2026 年 6 月与 Linux Foundation 联合公布这一变化。OpenSharing 将零拷贝共享对象从数据表扩展到 Agent Skills、AI 模型和非结构化数据，同时继续面向跨云、跨平台协作；Databricks 称，Delta Sharing 当时已覆盖超过 28,000 个数据接收方，约三分之一的共享通过开放连接器跨平台流转。该能力主要适用于企业与合作伙伴、客户或内部团队共享数据及 AI 资产，并减少文件导出和重复 ETL；但本文提供的内容未完整说明底层协议、权限治理和兼容性变化。

### [AgentCore Web Answer 上线](https://aws.amazon.com/blogs/machine-learning/getting-started-with-web-answer-on-amazon-bedrock-agentcore/) ⭐️ 8.0/10

AWS 宣布 Web Answer 已在 Amazon Bedrock AgentCore 正式可用，智能体通过一次工具调用即可获得基于当前网页来源生成的综合答案，并附带将事实主张映射到来源 URL 的引用。该能力由 AgentCore Gateway 以托管连接器方式提供：Web Answer 负责规划搜索、并行检索、阅读页面、补充搜索、答案综合和归因，Gateway 则通过 IAM 或 JWT 认证并以 MCP 工具结果返回内容。它适合需要实时互联网信息和可追溯引用的企业智能体子任务；AWS 对实时性、智能搜索和负责任 AI 防护的描述属于厂商宣称，材料未提供定价、权限细节或效果验证数据。

rss · AWS Machine Learning Blog · 11月5日 21:04

**「背景」** 此前的 Horizon 日报曾介绍，AgentCore Gateway 可将企业现有 REST API 统一转换为受权限控制的智能体工具，并由平台团队集中维护 MCP 层（2026-10-30）【tool-1-1】。另有 2026-11-04 的报道展示了 Gateway 通过代理用户令牌交换保留发起人的身份调用 ServiceNow，这与本次 Web Answer 由 Gateway 认证请求、再以自身服务角色调用 AWS 托管连接器的模式形成对照【tool-1-2】。

**「平台启示」** Web Answer 将搜索、内容获取、综合和引用从应用侧自建流程收拢为一个托管工具，同时保留 Web Search 这种只返回原始结果、由应用自行控制综合的模式，体现了企业 AI 平台可按任务复杂度提供分层工具接口：需要快速、带引用的事实回答时使用高集成工具，需要掌控检索与生成流程时使用低集成工具。

### [Neo4j 发布本体图规范](https://neo4j.com/blog/developer/the-neo4j-ontology-graph-specification-a-pragmatic-open-ai-first-approach/) ⭐️ 8.0/10

Neo4j 发布开源的 Ontology Graph Specification，以机器可读形式描述实体、关系、属性和业务含义，用于在数据、应用与 AI 系统之间共享领域知识。该规范采用面向图的表示方式，提供与部分 RDFS 和 SHACL 构造的映射，并面向知识图谱构建、GraphRAG 检索、数据约束以及 AI 智能体语义理解等企业场景。Neo4j 宣称同一本体可支持验证、集成、检索和数据丰富等多种用途，但文章未说明规范版本、成熟度、定价、外部生态采纳情况或可复核的客户效果。

rss · Neo4j Blog · 11月5日 19:57

**「背景」** 企业本体通常用于显式定义业务实体、关系、属性及约束，为知识图谱、数据集成和 AI 系统提供共享语义。Neo4j 此前已支持与 RDF、RDFS、OWL 等 W3C 标准互操作；其中 SHACL 是 W3C 用于描述和验证 RDF 图结构约束的标准，本次规范进一步面向图数据库与 AI 应用提供本体表示，并记录与部分 RDFS、SHACL 构造的映射。

**「建模启示」** 该规范体现了一种将图结构与业务定义、同义表达和标识规则放在同一语义层中的建模方式，使数据库约束、知识图谱逻辑、GraphRAG 和智能体上下文能够复用同一领域模型。对 CRM+AI 平台而言，这种分层可用于区分底层数据模式与面向业务概念的语义定义，减少不同应用分别维护实体含义的成本。
